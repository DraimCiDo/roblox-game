# Процесс разработки

## Ветки
- `main` — всегда собирается и запускается. Прямые пуши запрещены (включите branch protection в настройках GitHub: require PR + require CI).
- Рабочие ветки: `feat/...`, `fix/...`, `chore/...`, `docs/...`.

## Цикл задачи
1. Задача = GitHub Issue (шаблоны в `.github/ISSUE_TEMPLATE`).
2. Ветка от свежего `main`: `git switch -c feat/coins main`.
3. `rojo serve` + Studio, разработка, проверка Play.
4. `./scripts/check.ps1` (или `.sh`).
5. Коммиты: `feat(coins): ...`, `fix(data): ...`.
6. PR по шаблону → CI зелёный → ревью другого человека → Squash and merge.

## Работа с ИИ-агентами
- Агенту давайте задачу как Issue: что нужно игроку, критерии готовности, ссылка на раздел GDD.
- Крупную задачу — сначала попросить план, согласовать, потом реализацию.
- Каждый агент работает в своей ветке. Для параллельной работы — `git worktree add ../game-feat-x feat/x`.
- Код агента ревьюит человек так же строго, как код человека. Особое внимание: валидация Remotes, данные игрока, утечки памяти.
- Правила агентов — `AGENTS.md`. Если агент систематически ошибается в чём-то — добавьте правило туда или новый скилл в `.claude/skills/`.

## Карта и ассеты
- Скрипты — в Git. Карта и модели — в Roblox (Team Create или опубликованное место).
- Модели, которые нужно версионировать, можно сохранять как `.rbxm` в `assets/` и подключать через Rojo.
