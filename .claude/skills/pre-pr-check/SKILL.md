# Проверка перед PR

## 1. Автоматика
```bash
stylua src            # исправить формат
./scripts/check.sh    # Windows: ./scripts/check.ps1
```
Все три шага (StyLua, Selene, Rojo build) должны пройти. Предупреждения Selene — исправить, а не подавлять. `-- selene: allow(...)` только с комментарием почему.

## 2. Самопроверка диффа (`git diff main...HEAD`)
- [ ] Нет отладочных `print` (оставлять только `warn` для реальных ошибок).
- [ ] Нет изменений в `Packages/`, `*.rbxl`, `sourcemap.json`.
- [ ] Каждый `OnServerEvent` / `OnServerInvoke` валидирует аргументы (скилл `new-remote`).
- [ ] Таблицы по игроку чистятся в `PlayerRemoving`.
- [ ] Нет `wait()`, `spawn()`, `delay()` — только `task.*`.
- [ ] Изменена схема данных → выполнен скилл `datastore-change`.
- [ ] Дифф решает одну задачу. Посторонний рефакторинг — отдельным PR.

## 3. Коммит и PR
- Ветка: `feat/...`, `fix/...`, `chore/...`, `docs/...` — не `main`.
- Сообщение коммита в стиле Conventional Commits: `feat(combat): добавить урон от падения`.
- PR по шаблону `.github/pull_request_template.md`: раздел «Как проверить» с шагами в Studio обязателен.
- Не мержить свой PR самостоятельно — нужен ревью человека.
