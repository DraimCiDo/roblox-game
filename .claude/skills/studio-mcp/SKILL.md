# Roblox Studio через MCP

Настройка сервера — `docs/MCP.md`. Studio должен быть открыт, плагин MCP активен, Rojo подключён (`rojo serve`).

## Главное правило
**Источник истины для кода — файлы в `src/`, а не Studio.**
Скрипты меняются только в репозитории, Rojo синхронизирует их в Studio.
Код, созданный через MCP прямо в Studio, при следующей синхронизации может быть потерян и не попадёт в Git.

## Можно через MCP
- Читать иерархию (Workspace, ReplicatedStorage), свойства объектов, ассеты карты.
- Выполнять **временный** диагностический код (`run_code`): напечатать состояние, проверить гипотезу.
- Запускать/останавливать плейтест и читать Output, чтобы проверить свою правку.
- Вставлять ассеты (модели, части) в Workspace, если задача про уровень/карту — и потом сообщить человеку, что место нужно сохранить (карта живёт в .rbxl, не в Git).

## Нельзя через MCP
- Создавать или редактировать Script / LocalScript / ModuleScript, синхронизируемые Rojo.
- Удалять объекты в Workspace без явной просьбы человека.
- Публиковать место (Publish to Roblox) — только человек.
- Вставлять модели из Toolbox (могут содержать вредоносные скрипты).

## Цикл проверки правки
1. Изменить файлы в `src/`.
2. Убедиться, что Rojo синхронизировал (иерархия в Studio обновилась).
3. Запустить плейтест через MCP, дождаться загрузки, прочитать Output.
4. Нет ошибок/предупреждений от нашего кода → остановить плейтест, отчитаться.

Если MCP-сервер недоступен — не имитировать результат. Сообщить человеку и попросить проверить вручную по шагам.
